## Дополнение 0.2.0: Cursor

Каталог `.cursor/projects` и ручной импорт файловых JSONL-транскриптов поддерживают записи `role=user|assistant` с объектом `message` и массивом `content`. Неизвестные формы отклоняются. Это не адаптер SQLite и не поддержка всех версий Cursor; один файл рассматривается как одна сессия. Сохраняется вся запись с номерами строк. Лимит нативного импорта — 1 GB; большие файлы обрабатываются потоково. Изменение баз Cursor и автоматическое создание чата не выполняются.

# Истории агентов — 0.1.19 Preview

Первый этап интеграций: чтение выбранного JSONL-файла Codex или Claude Code без изменения исходника.

1. Откройте «Агенты и контекст», выберите агента.
2. Нажмите «Открыть JSONL-историю агента…». Диалог открывает обнаруженное стандартное расположение; выберите одну завершённую сессию.
3. Проверьте число сообщений и остальных сохранённых записей.
4. Выберите локальную модель и подготовьте контекст. До генерации сохраняется проверенная копия загруженного исходника.
5. Проверьте итог и перенесите его в новый чат выбранного агента.

| Агент | Поддерживаемые признаки |
|---|---|
| Codex | `session_meta.payload.id`, `response_item.payload.type=message`, роль сообщения |
| Claude Code | `sessionId`, `user/assistant`, объект `message` с ролью |
| Остальные 9 агентов | Универсальный импорт экспорта TXT/MD/JSON/JSONL |

Это адаптеры структуры, а не гарантия поддержки всех версий продуктов. Неизвестные поля и события остаются целиком; формат без распознаваемых сообщений или с несколькими ID сессий отклоняется. Повреждённый JSONL также отклоняется. Лимит файла — 30 MB. Чтение выполняется вне основного потока интерфейса.

Сохраняются исходные номера строк. Порядок соответствует файлу; ветки и события компактизации не превращаются в одну доказанную хронологию. Результаты инструментов и неизвестные записи не отбрасываются. Инструкции внутри истории считаются данными. Чувствительные данные могут находиться в исходнике и его локальной резервной копии; она хранится с правами 0600 в каталоге 0700.

Оригинал не переписывается, не удаляется и не уменьшается на диске. Это подготовка контекста для нового чата, а не освобождение места. Автокаталог сессий, восстановление активной ветки, остальные нативные адаптеры и проверка семантического качества на реальных локальных моделях остаются следующими этапами.

Источники структуры:
- https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/common/rollout.rs
- https://code.claude.com/docs/en/sessions

Проверки используют синтетические истории, не содержимое пользовательских чатов: неизвестные события, инструменты, ветки, неверный агент, смешанные ID, повреждённый JSONL, номера строк и резервная копия после изменения источника.

## 0.1.20 — список сессий

«Найти сессии» обходит стандартные каталоги выбранного Codex/Claude Code. Список содержит только метаданные JSONL: имя, путь, дату изменения и размер. Это кандидаты: структура и ID проверяются при открытии. Поиск фильтрует имя и путь, не содержимое. Показ по 20 строк, новейшие сверху. Предел — 20 000 объектов файловой системы; ошибки и ограничение явно отмечаются. Ссылки и облачные объекты не обходятся. Нестандартное расположение доступно через ручной выбор файла.

Дата изменения не определяет активность сессии. Автоматическое восстановление ветки и другие нативные адаптеры пока не реализованы.

## 0.1.21 — большие JSONL

Нативный импорт принимает до 1 GB. Файлы больше 30 MB копируются блоками в уникальную временную папку с правами 0700; файлы имеют права 0600. SHA-256 относится к загруженным байтам. Размер, время изменения и идентификатор исходного файла повторно проверяются после копирования. Изменение источника прерывает импорт. Затем снимок проверяется построчно и создаётся файл с разметкой исходных строк.

Локальная модель читает разметку порциями до 12 000 символов. Одна запись JSONL ограничена 8 MiB. Итоговые заметки ограничены 8 MB: превышение прерывает генерацию с ошибкой, не выдавая усечённый итог. При прерывании промежуточный пересказ не сохраняется; оригинал и созданная резервная копия остаются. Полный пересказ сотен мегабайт может занять очень долго.

Прогресс импорта включает копирование и проверку (два прохода). Временный снимок освобождается вместе с импортом; после завершения процесса возможны остатки в системной временной папке. При подготовке пересказа создаётся отдельная резервная копия, проверяемая SHA-256. Для операции нужно дополнительное место на диске. Это не очистка оригинальной истории.

## Актуальная матрица 0.3.0

| Агент | Файлы, распознавание и ограничения |
|---|---|
| Codex / Claude Code / Cursor | Прежние файловые JSONL; до 1 GB, запись до 8 MiB |
| Gemini CLI | JSON snapshot: sessionId/messages; JSONL: sessionId, user/gemini content. Patch-события сохраняются, но не реконструируют актуальную ветку |
| Continue | JSON sessionId/history/message.role/content |
| Cline / Roo Code | Массив сообщений в api_conversation_history.json; роли и content; файлы UI-событий не принимаются за историю модели |
| Copilot / Windsurf / Aider / OpenCode | Универсальный экспорт; специализированного чтения базы нет |

JSON целиком ограничен 30 MB. Неизвестные поля остаются в нормализованных записях. Ссылки `[L…]` для JSON означают номера этих записей, а не физические строки исходного файла. Исходные байты сохраняются в проверенной резервной копии. Каталог ищет кандидатов по метаданным, полная проверка выполняется при открытии.

Сравнение показывает первые 50 000 символов размеченного исходника рядом с результатом. Для проверки остальной истории нужен оригинал. Импорт и генерация не объединяют разных агентов, не переписывают активный диалог и не уменьшают его файл.
