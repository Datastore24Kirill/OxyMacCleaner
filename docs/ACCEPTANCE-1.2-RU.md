# OxyMac Cleaner 1.2 — приёмка сборок 58 и 59

Актуальная сводка на 15 октября 2026: публичная версия — **1.1.0**, установлена **1.2.0 (58)** с подтверждёнными пробами доступа к диску; подготовлена **1.2.0 (59)**, ещё не установленная и не прошедшая живую UI-приёмку. [Единый текущий статус](STATUS.md).

Ниже сохранены доказательства и последовательность событий 13 октября. 246 тестов, CI `c340985` и замеры производительности относятся к build 58; целевые проверки build 59 перечислены отдельно в конце. Они не означают полную приёмку build 59. Исправления исходников от 15 октября и их целевые проверки описаны отдельно ниже; они не включены в Release-сборки 58/59 и не заменяют живую UI-приёмку.

## Изменения build 58 — 13 октября

1. Незавершённая UI-проверка 1.1 (агенты, объяснения, следующая страница файлов) остаётся открытой: при повторной попытке служба управления интерфейсом вернула `Sky Computer Use native pipe closed before response`. На этапе подготовки доступ к UI не был восстановлен, поэтому замена установленной 1.1 была отложена. Последующая установка build 58 описана ниже.
2. Ограниченный LRU-кэш готовых запросов файлов: до четырёх результатов, суммарно до 1600 строк. Для первой страницы 200 строк без возрастного фильтра в том же проходе подготавливаются следующие 200; показ и выбор остаются ограничены текущей страницей. Отдельный кэш карты — до четырёх папок, суммарно до 8000 узлов. Большие результаты не кэшируются. Изменение снимка или исключений создаёт новый файловый индекс. Фильтры по возрасту не кэшируются: результат зависит от текущего времени. Отмена проверяется и при попадании в кэш. Кэш не является разрешением на удаление; перед действиями остаются свежие проверки. Сокращены преобразования путей при построении карты.
3. Каталог метаданных приложений из `/Applications` и пользовательской папки Applications (корень и одна вложенная группирующая папка). Сверка точного ID контейнера с Info.plist только при единственном совпадении; групповые контейнеры не приписываются одному приложению. Для явно выбранного проекта показывается найденный маркер. Владелец по метаданным отличается от предположения по пути, основание доступно в подсказке. Неизвестный владелец остаётся неизвестным; отсутствие приложения не означает разрешение удалить его данные. Каталог читается в фоне, содержимое пользовательских документов не анализируется.
4. Узкие Python-кэши поддерживают также `pytest.ini`, `ruff.toml`, `.ruff.toml`. Это расширение вариантов конфигурации уже поддержанных инструментов, не универсальная очистка кэшей. Нужны точная подпись CACHEDIR.TAG, корень Git, ignored/untracked, отсутствие активности, давность записей, неизменность метаданных и манифеста. SQLite, исходники и секреты остаются защищёнными. У pytest теряется список прошлых ошибок, Ruff пересоздаёт кэш при следующем запуске. Проверки конфигурации не являются полным TOML/INI-парсером.
5. Сводка сохранности формулировок по категориям в результате оптимизации. Для текущего редактируемого текста отдельно считаются ссылки и присутствие дословной формулировки проверяемого черновика. Пересчёт в фоне с отменой, после редактирования. Это не оценка смысла всей истории и не доказательство актуальности; сравнение с исходником остаётся отдельным действием. Заголовок результата теперь «Результат для проверки».

## Проверки build 58 — 13 октября

Полный прогон build 58: 246 тестов, 0 ошибок, 45,52 секунды. После профилирования заменён дорогостоящий поиск подстроки в нормализованных путях на буквальный NSString-поиск; проверены регистр, диакритика, русский и японский текст. Замер реального неизменённого снимка 6 092 958 файлов в Debug: загрузка 129,42 с; поиск Downloads — 24,39 с, 12 411 совпадений, 200 строк; повтор — 0,000010 с. До финального добавления подготовки следующей страницы расширение до 400 строк занимало 46,87 с (повторный полный проход), карта корня — 22,85 с, повтор — 0,000009 с. Пик RSS 5 314 740 224 байта, footprint 5 774 283 432 байта. До замены строкового поиска в этой же серии первый запрос занимал 173,23 с, расширение страницы 183,36 с; загрузка 94,89 с, карта 13,77 с. Между прогонами различалась нагрузка, параллельно выполнялись сборка/тесты. Это не контролируемое обещание ускорения и не доказательство снижения базового потребления памяти. Профилирование первого прогона указывало на String.contains в фильтре.


Финальный замер после подготовки второй страницы (коммит `c340985`): загрузка 63,47 с; первый поиск 32,22 с; повтор 0,000012 с; 400 строк 0,000002 с; первая карта 28,91 с, повтор 0,000007 с. Всего 125,23 с. Пик RSS 5 665 406 976 байт, footprint 5 937 320 688 байт: снижение базовой памяти не подтверждено. Следующая архитектурная задача — хранение индекса на диске/чтение частями, а не утверждение, что кэш устранил эту проблему. Проверка метаданных на текущем Mac обнаружила 108 приложений, один выбранный проект; пакет установленного OxyMac Cleaner определён по Info.plist.

Скрипт воспроизведения: `scripts/quality/snapshot_browser_benchmark.swift`, принимает явно выбранный снимок, выводит только количество и время. SHA-256 пользовательского снимка после замера совпадает с приёмкой 1.1. Подготовлен `dist/OxyMacCleaner-1.2.0-macOS-arm64.zip`; build 58, ad-hoc codesign и SHA256SUMS прошли. ZIP build 58 содержал 9 026 333 байта, контрольная сумма сверена после повторной упаковки. На момент этой проверки сборка ещё не была установлена; последующая установка описана ниже. Этот размер не относится к позднее подготовленному ZIP build 59. Публичный релиз 1.2 не создан. Первый вариант проверен в коммите `366f998`; [успешный CI](https://github.com/Datastore24Kirill/OxyMacCleaner/actions/runs/38357436745). Новые сценарии проверяют ограничения LRU, отмену при попадании в кэш, зависимость возрастного фильтра от времени, изменение исключений, границы папок, неоднозначные ID приложений, раздельный подсчёт ссылок/формулировок, изменение конфигурации кэша после предпросмотра. Удаляются только собственные фикстуры тестов.

## Локальная установка 13 октября — выполнена, выпуск удержан

Установлена 1.2.0 (58) по каноническому пути `/Users/oxyfire/Applications/OxyMac Cleaner.app` из проверенного ZIP. Перед заменой два замера CPU показывали 0%, время CPU не изменилось; sample показывал ожидание событий/рабочего потока, открытых файлов обхода или очистки не было. Использован штатный UpdateInstaller: получен `healthy`, журнал подтвердил успешный запуск. Версия 1.1.0 (57) сохранена в rollback под исходным именем приложения. Проверка целостности подписи установленного пакета прошла. Файл настроек непосредственно после установки побайтно совпадал; SHA-256 снимка после проверки — `7db7f2addfc648666cc1c070f2c344aca8779c24c1ae35892fefe77d1c605513`, без изменений.

Живой UI подтвердил версию 1.2.0, загрузку 6 092 958 файлов, логический размер 1,82 TB и выделенный 871,87 GB. После повторного запуска виден прогресс загрузки снимка. Новое сканирование и удаление пользовательских данных не запускались.

При первоначальной проверке после установки Full Disk Access **не был подтверждён** (восстановлен в продолжении ниже): внутри приложения — отказ, в системных настройках переключатель включён. Попытка повторно добавить точный установленный пакет через системный диалог не завершилась: ввод пути и действия диалога работали некорректно. Настройки TCC напрямую не менялись. Наличие галочки не засчитано как успешная проверка.

Управление UI временно восстановилось после установки, затем снова отказало при переходе в «Агенты и контекст». Локальный crash report SkyComputerUseService от 13 октября содержит EXC_BREAKPOINT/SIGTRAP и Array.remove(at:) в стеке; это падение службы автоматизации, не установленный факт падения Cleaner. Сам процесс Cleaner оставался запущен. Проверки сводки агентов, объяснений, контекста и следующей страницы остаются открыты. Публичный релиз 1.2 не создан.

В установленной сборке 58 после повторного добавления/запуска живой экран проверки сообщил «Проверенные защищённые папки доступны». Полный снимок снова загружен.
