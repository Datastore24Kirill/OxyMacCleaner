# Рабочие деревья Git — 0.1.17

В Xcode и проекты → Рабочие деревья выберите репозиторий. Можно выбрать основной checkout или дополнительный: приложение определит основной и покажет зарегистрированные Git рабочие деревья. Это не глобальный поиск всех репозиториев на диске и не интеграция с внутренней базой задач агента.

Показываются путь, ветка/HEAD, размер и последнее изменение (когда проверка файлов возможна), а также причина блокировки. Размер логический; размер основного/недоступного дерева может оставаться неизвестным. Карточка в Возможностях очистки использует последний результат этого отдельного анализа.

## Условия предложения удаления

- Только дополнительное зарегистрированное дерево, основной checkout защищён.
- Путь канонический, не системный и не исключён пользователем; проверены общий Git-каталог и обратная ссылка регистрации на .git.
- Нет изменений, untracked **и ignored** файлов. Игнорируемые данные тоже могут быть ценными.
- Нет специальных флагов индекса assume-unchanged/skip-worktree, подмодулей, locked/prunable/неизвестного состояния.
- Все коммиты HEAD достижимы из локальных remote-tracking refs. Без refs кандидат блокируется. Сеть и fetch не используются: это не подтверждение наличия данных на сервере сейчас.
- Последнее изменение файлов и корневого каталога старше 30 дней; это не доказательство последнего использования.
- lsof не видит открытых файлов/cwd в каталоге; ошибки, предупреждения или таймаут блокируют удаление. Невидимый процесс или задача агента без открытого файла не могут быть надёжно распознаны.

## Удаление

Перед подтверждением создаётся полный манифест дерева. Затем ещё раз проверяются регистрация, Git-состояние, исключения, активность и манифест. Операция — `git worktree remove -- <точный путь>` без `--force`, prune, удаления веток или файлов вручную. После команды проверяются регистрация и отсутствие пути. Один объект за одну операцию. Есть запись результата в истории.

Это прямое удаление рабочей папки без карантина. Общий репозиторий и ветка остаются; checkout можно воссоздать из сохранённого коммита. Автоматического восстановления папки в интерфейсе нет. Перед подтверждением пользователь должен закончить связанные задачи и закрыть редакторы. Между проверкой и Git нет глобальной блокировки всех внешних процессов; не запускайте работу в удаляемом дереве.

Команды вызываются без shell; Git fsmonitor и hooks отключены для этих вызовов, переменные GIT_* от окружения запуска не наследуются. Таймаут одной команды 60 секунд, ограничение результата 16 MB. Отмена обрабатывается между командами; Git-команда удаления должна завершиться.

## Что остаётся дальше

Автоматическое обнаружение репозиториев агентов, подтверждение статуса их задач, поддержка дополнительных версий/форматов и отдельные правила генерируемых данных/зависимостей пока не реализованы. Не расширяем удаление на неизвестные данные.

Источники: [git-worktree](https://git-scm.com/docs/git-worktree), [git-status](https://git-scm.com/docs/git-status). Проверки выполняются на собственных временных репозиториях; пользовательские деревья не удаляются при разработке.
