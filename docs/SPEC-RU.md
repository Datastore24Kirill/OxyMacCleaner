# OxyMac Cleaner — техническое задание первой версии

Дата фиксации: 6 октября 2026 года.

**Статус:** проектирование. Фиксация ТЗ не означает запуск разработки, установки компонентов или очистки компьютера.

OxyMac Cleaner — бесплатное приложение с открытым исходным кодом для **Mac на Apple Silicon**. Оно помогает находить ненужные файлы, освобождать место после разработки под iOS и подготавливать сокращённый контекст для продолжения работы с агентами.

Проект публикуется на GitHub. Пользователю предоставляется готовая сборка, не требующая самостоятельной компиляции.

CleanMyMac используется как референс организации сканирования и просмотра результатов. Название, графика и интерфейс — собственные.

## 1. Границы первой версии

В первую версию входят:

- Анализ занимаемого места, крупные файлы и папки.
- Поиск точных дубликатов.
- Поиск старых загрузок, установщиков, архивов и сборок.
- Очистка данных Xcode и управление ненужными симуляторами.
- Анализ генерируемых файлов проектов.
- Анализ локальных данных популярных агентов.
- Сокращение контекста отдельно для каждого агента и каждой выбранной сессии.
- Помощь в установке и запуске локального движка без терминала.
- Карантин, восстановление и напоминания каждые пять дней.
- Готовая сборка, обновления с прогрессом и восстановлением предыдущей версии при неудаче.

Не входят: поддержка Intel Mac, антивирус, «ускорение RAM», очистка системных компонентов неизвестного назначения, объединение историй разных агентов, облачная обработка контекста.

## 2. Основные принципы

**Сканирование ничего не изменяет.** Любое перемещение, архивирование или удаление выполняется отдельным действием.

**Большой или старый файл не считается мусором автоматически.** Приложение объясняет, почему объект предлагается к рассмотрению.

**Сокращение текста не гарантирует сохранения каждой детали.** Исходная история сохраняется, а результат доступен для проверки и редактирования.

**Место в карантине остаётся занятым.** Интерфейс различает найденный объём, выбранный объём, размер карантина и фактически освобождённое место.

**Данные обрабатываются локально.** Сеть используется для получения обновлений, движка и моделей. Содержимое файлов и чатов никуда автоматически не отправляется.

- Для объекта: **«Показать в Finder»**, **«Исключить»**, **«Защитить»**, доступное действие очистки.

## 4. Сканирование и поиск дубликатов

Пользователь выбирает области сканирования. Недоступные папки отображаются отдельно: неполная проверка не выдаётся за полную.

Сканер должен:

- Показывать результаты постепенно.
- Не обходить символические ссылки бесконечно.
- Не запускать скачивание облачных файлов ради анализа без отдельного согласия.
- Учитывать жёсткие ссылки и особенности хранения APFS при оценке освобождаемого места.
- Не включать вложенные объекты дважды в итог выбранной очистки.
- Повторно проверять объект перед перемещением: файл мог измениться после сканирования.

Поиск дубликатов: размер → проверка содержимого → подтверждение точного совпадения перед действием. Совпадающее имя не является доказательством.

Последнюю копию в группе нельзя убрать через действие «Очистить дубликаты». Одинаковые файлы в разных проектах не считаются взаимозаменяемыми зависимостями.

## 5. Очистка для разработчика

| Категория | Что показываем | Ограничения |
|---|---|---|
| **DerivedData** | Связанный проект, размер, дата изменения | Пропуск активной сборки; предупреждение о повторной компиляции |
| **`.xcarchive`** | Приложение, версия, номер сборки, дата, размер, наличие dSYM | Только явный выбор; закреплённые архивы защищены |
| **Runtime симулятора** | Версия, размер, связанные устройства, доступность операции | Удаление поддерживаемым инструментом; способ восстановления указан заранее |
| **Устройство симулятора** | Имя, runtime, размер данных, состояние | Запущенные устройства пропускаются; предупреждение о потере тестовых данных |
| **Генерируемые данные проекта** | Категория, проект, способ восстановления | Только распознанные правила; неизвестные каталоги не выбираются автоматически |
| **Старые рабочие деревья агентов** | Репозиторий, изменения, состояние использования | Незакоммиченные и незащищённые локальные данные блокируют рекомендацию очистки |

Исходники, ключи, сертификаты, provisioning profiles, файлы окружения и настройки агентов не включаются в рекомендуемую очистку.

Для архивов приложений предусматривается настраиваемое правило «сохранять последние N архивов каждого приложения». Оно формирует рекомендации, но не запускает удаление.

Для каждого адаптера интерфейс показывает отдельные возможности:

- Агент обнаружен.
- Объём данных определён.
- История доступна для чтения.
- Поддержан импорт истории.

Если история недоступна, предлагаем импорт поддерживаемого файла. Если безопасный способ не найден — функция явно недоступна. Поддержку одного формата нельзя обозначать как полную поддержку всего агента.

Работающие базы не редактируются напрямую. Неизвестные версии формата открываются только в режиме, который не изменяет данные.

## 7. Сокращение контекста

Основной сценарий:

1. Пользователь выбирает агента и одну сессию.
2. Приложение проверяет, что история доступна и сессия не изменяется.
3. Создаёт проверенную резервную копию исходных данных.
4. Показывает объём истории и параметры сокращения.
5. Локальная модель готовит описание состояния.
6. Пользователь проверяет и при необходимости редактирует результат.
7. Контекст экспортируется или передаётся в новую сессию поддерживаемым способом.

Если агент не поддерживает безопасное сокращение текущего чата, используется **подготовка новой сессии с сокращённым контекстом**, сохраняя исходную историю. Истории разных агентов не объединяются.

Содержание результата:

- Цель и актуальные требования.
- Ограничения и запреты.
- Принятые решения и причины.
- Изменённые файлы и связанные коммиты, если они известны.
- Проведённые проверки и их результаты.
- Ошибки, нерешённые вопросы и следующие действия.
- Ссылки на исходные сообщения и артефакты.
- Явные противоречия и неопределённость.

Содержимое истории рассматривается как данные: команды из старого чата не исполняются.

Предусматриваются режимы **«Бережный»**, **«Сбалансированный»**, **«Краткий»**. Их параметры определяются на тестовых историях. Размер результата показывается в символах и, при наличии подходящего токенизатора, в оценочных токенах.

**Не обещаем автоматического снижения расхода токенов существующего чата.** Подготовленный контекст становится полезен после фактического использования в продолжении работы.

Удаление исходной истории не является частью обязательного сценария сокращения. Архивирование и очистка — отдельные действия после проверки результата.

## 8. Локальный движок

Первый целевой вариант — интеграция с Ollama. Способ поставки и конкретная модель выбираются после проверки лицензий, совместимости и качества на Apple Silicon.

Мастер настройки:

1. Проверяет наличие совместимого движка.
2. Показывает источник загрузки, размер и условия использования.
3. Помогает установить и запустить движок без терминала.
4. Предлагает модель с учётом памяти и свободного места.
5. Показывает прогресс скачивания, отмену и повтор после ошибки.
6. Выполняет короткую локальную проверку работоспособности.

Если Ollama уже установлен пользователем, приложение не меняет его конфигурацию и не останавливает чужие задачи без согласия.

Без движка работают все обычные функции анализа и очистки. Сетевой сбой не блокирует работу с уже установленной моделью. Автоматического перехода на облачный сервис нет.

## 9. Карантин

Для каждого объекта сохраняются:

- Исходный путь и расположение в карантине.
- Дата операции, категория и размер.
- Метаданные, необходимые для восстановления.
- Результат операции и проверки целостности.

Правила:

- Объект считается помещённым в карантин только после успешного завершения операции.
- При переносе между дисками исходник удаляется только после проверки копии.
- Если исходный путь занят, восстановление предлагает выбор; существующие данные не перезаписываются молча.
- Если диск отключён, операция ждёт его подключения или предлагает другое место.
- Для данных, которые невозможно безопасно поместить в карантин, используется отдельный сценарий с явным предупреждением.

**Напоминание каждые пять дней**, пока карантин непустой. При пустом карантине уведомлений нет. После длительного отсутствия приложения показывается одно актуальное напоминание, а не накопленная очередь.

В уведомлении: количество объектов и занимаемое место. Действия: **«Открыть карантин»** и **«Напомнить позже»**. Следующее напоминание — через пять дней.

Окончательное удаление по умолчанию ручное, с подтверждением состава и объёма.

## 10. Разрешения, конфиденциальность и обновления

- Доступ запрашивается по мере необходимости с объяснением назначения.
- Для отказа в разрешении предусмотрен рабочий частичный режим.
- Постоянный запуск всего приложения с правами администратора не допускается.
- Истории и резервные копии доступны только текущему пользователю в рамках возможностей файловой системы.
- Диагностика не содержит текстов чатов, секретов и содержимого файлов по умолчанию.
- Отправка диагностического отчёта не выполняется автоматически.
- Приложение скачивается готовой сборкой; установка инструментов разработки пользователю не нужна.
- Обновление показывает этапы, проверяет целостность и сохраняет предыдущую версию.
- После обновления проверяется успешный запуск; при неудаче предусмотрен откат.
- Подпись Developer ID и notarization остаются отдельной задачей распространения. Их отсутствие обозначается честно.

## 11. Проверяемые критерии готовности

| Область | Условие приёмки |
|---|---|
| **Сканирование** | На контрольном наборе не меняются файлы; ошибки доступа и неполные результаты видны |
| **Отмена** | Сканирование прекращается, интерфейс остаётся доступным, частичные результаты обозначены |
| **Дубликаты** | Разные файлы одинакового размера не объединяются; последняя копия защищена |
| **Изменение после сканирования** | Изменившийся объект не удаляется по устаревшему результату |
| **Xcode** | Активные сборки и запущенные симуляторы не очищаются |
| **Карантин** | Проверены помещение, восстановление, конфликт пути, нехватка места и прерывание операции |
| **Учёт места** | Перемещение в карантин не отображается как освобождение всего объёма |
| **Напоминания** | Проверены пять дней, пустой карантин, перезапуск приложения и отсутствие повторного спама |
| **Контекст** | На контрольных историях проверено сохранение обязательных требований, решений и незавершённых задач; оригинал остаётся доступным |
| **Агенты** | Для каждого заявленного адаптера есть поддерживаемые версии, тестовые данные и явные ограничения |
| **Локальность** | После установки компонентов сокращение работает без интернета; содержимое историй не отправляется наружу |
| **Движок** | Проверены новая установка, существующая установка, отмена загрузки и нехватка памяти |
| **Обновление** | Проверены успешная установка, повреждённая загрузка и откат после неудачного запуска |
| **Интерфейс** | Проверены обе темы, RU/EN, управление с клавиатуры и основные сценарии VoiceOver |

Конкретные показатели скорости и потребления памяти фиксируются после прототипа на согласованных Mac и наборах данных. До измерений численные обещания не задаются.

## 12. Порядок реализации после утверждения ТЗ

1. Проверка форматов агентов, инструментов Xcode и минимальной версии macOS.
2. Макеты экранов и прототип сканирования без изменения файлов.
3. Карантин и восстановление с испытаниями сбоев.
4. Категории очистки, дубликаты и инструменты разработчика.
5. Локальный движок и сокращение контекста.
6. Интеграции агентов с матрицей проверенных возможностей.
7. Сквозные испытания, документация и готовая публичная сборка.

Перед началом разработки остаётся технически подтвердить **минимальную macOS, модель для локального сокращения и точные возможности адаптеров**. Это исследовательские задачи первого этапа; согласованные продуктовые требования от них не меняются.

## 13. Зафиксированные решения пользователя

- Название: **OxyMac Cleaner**.
- Проект бесплатный и публичный на GitHub.
- Первая версия — только для Apple Silicon.
- Обработка контекста полностью локальная.
- Подготовка сокращённого контекста входит в первую версию.
- Поддержка максимально широкого списка популярных агентов с честной матрицей возможностей.
- Контекст обрабатывается отдельно для каждого агента; объединение историй не требуется.
- Приложение помогает скачать и запустить локальный движок.
- Если текущий чат нельзя безопасно сократить, подходит подготовка новой сессии.
- Карантин обязателен; напоминание каждые пять дней, удаление по умолчанию ручное.
- На текущем этапе выполняется только планирование и фиксация документации.
