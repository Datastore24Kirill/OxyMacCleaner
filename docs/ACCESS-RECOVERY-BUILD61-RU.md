# Сборки 60/61 — восстановление доступа и исправления перезапуска

15 октября 2026. Продолжение [приёмки build 60](ACCEPTANCE-BUILD60-RU.md); предыдущий отчёт сохраняет результаты на момент первоначальной установки. [Текущий статус](STATUS.md).

## История: восстановление доступа build 60

В установленной **1.2.0 (60)** восстановлен доступ: экран самого приложения сообщил **«Проверенные защищённые папки доступны»**. Это подтверждение текущих проб, а не обещание доступа ко всем файлам или сохранения разрешения после смены ad-hoc подписи.

В системных настройках использован «+» и выбран точный пакет `/Users/oxyfire/Applications/OxyMac Cleaner.app`. Путь передан через `setValue` в поле Go To системного диалога, затем выполнен системный Restart. После этого пробы внутри приложения прошли.

До восстановления обычный запуск через Launch Services также оставлял отказ. Поэтому способ запуска **не доказан как причина** отказа. Успешный результат относится к последовательности повторного добавления точной копии и системного перезапуска.

## Найденный сбой перезапуска

При живой проверке помощник перезапуска ожидал завершения исходного PID, но процесс не завершался; кнопка оставалась недоступной. После закрытия sheet команда Cmd+Q завершила приложение.

В исходниках подготовлены исправления:

- закрытие sheet перед завершением приложения;
- журналирование перезапуска;
- восстановление интерфейса после тайм-аута вместо постоянной недоступности кнопки.

Helper-тесты — **PASS**. Окно доступа упрощено. **Swift-сборка прошла за 36,53 с**, `git diff --check` — без замечаний. Затем выполнены дополнительные правки и финальная Release-упаковка 61, описанная ниже.

## Дополнительная защита перед завершением процесса

Финальное QA-ревью выявило окно гонки около 350 мс: после запроса перезапуска пользователь мог успеть начать новую операцию до завершения процесса. В исходниках основной интерфейс и меню блокируются при `vm.restartingForAccess`; отложенный callback повторно проверяет занятость и обработку контекста. Если новая операция уже началась, отменяется только помощник перезапуска, а операция не прерывается.

После этой правки Release build 61 пересобран. Итог финальной упаковки и живой проверки приведён ниже.

Повторное падение службы на разделе агентов ограничило проверки. После ручного перехода в Files управление восстановилось и установка была выполнена.

## Частичная живая проверка Files на build 60

После ручного переключения пользователем в «Файлы» CUA снова смог читать интерфейс. Поэтому весь GUI не считается недоступным: повторяемый сбой остаётся связан с проверкой раздела агентов, а Files доступен после переключения.

В build 60 подтверждены Stop и Retry. После Stop одновременно отображались «Подготовка остановлена» и ошибочное «Нет подходящих файлов»; Retry снова показывал прогресс. Stop повторно подтверждён чтением accessibility-состояния. Пользовательские данные не изменялись.

Для снимка примерно 7 млн записей подготовка спустя около минуты показывала лишь 1%, затем 2%. Это наблюдение интерфейса, не точный benchmark. Пагинация и переход к следующим 200 строкам не проверены.

В исходниках `FileBrowserView` показ пустого результата дополнительно ограничен условием `failure == nil`, чтобы состояние остановки не сопровождалось ложным пустым результатом. Правка включена в финальную упаковку и установленную build 61. Её результат после Stop в живом UI 61 ещё не проверен. Хеш предыдущей промежуточной упаковки не используется для финального артефакта.
